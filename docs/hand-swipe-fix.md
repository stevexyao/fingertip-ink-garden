# 双手挥动切花修复

本次针对实际操作反馈复查了从摄像头结果到双手状态、花型选择和界面显示的完整链路。

## 已复现的原因

- 固定要求横移22%画宽，导致正常小幅度挥动漏切；180毫秒的移动下限也会拒绝连续多帧快挥。
- 每帧都要求完全舒掌，挥动时轻微张合波动会抹掉已采集轨迹。
- 固定18%画宽的接近保护会将两只并未重叠的小手误认为遮挡；同x但上下分开的双手曾被误认为交叉。
- 推理完成时间兼作动作采样时间，耗时抖动可能改变运动速度判定。
- 手离场后，旧手动花型偏好可能覆盖挥手选中的新花型。

## 修复后的行为

- 以可见掌宽计算挥动幅度，并限制在画面宽度10%–18%；允许连续多帧快挥，至少需要两段实质移动来拒绝单帧跳点。
- 采用舒掌开启、明显收拳取消的迟滞规则，正常张合抖动不再丢失整段挥动。
- 双手接近判断随掌宽变化，分别识别两手同向、向外和向内动作；真正重叠、交叉或身份不明时继续保护。
- 动作采样时间与结果到达时间分开：前者用于运动，后者用于显示新鲜度和切换后的冷却。
- 每手保持独立花型；一次动作切一档；显示切换后冷却约900毫秒。手动选花也从实际操作时刻计算冷却。
- 只消费尚未应用的点选指令；离场再入镜保留最新花型。双手同时切换时合并显示两朵花的提示。

## 验证方法与边界

单元测试覆盖自然小幅度、快挥、斜向、轻微张合、近距平行、上下分离、低帧率、冷却、跳点、慢漂、交叉与离场重入。

浏览器集成检查使用Google官方手图检测出的每手21点，再对这些点生成可控运动轨迹。保留实际摄像头生命周期、应用回调、手势引擎、花型状态与页面，替代物理摄像头输入，以便重复验证两朵花是否真的切换。

这属于模拟轨迹的浏览器集成检查，不等于真人摄像头挥动验收。低帧率下，快于一帧的动作仍可能漏检；请舒掌短暂停稳后，自然横向挥动，并避免两手完全重叠。
