# 声控存画：说“截图”截取当前国画

声控与摄像头、音乐分别开启。页面默认不监听；只有点击“开启声控”，浏览器才会请求麦克风。普通页面与沉浸模式的开关同步，切到后台或离开页面会停止监听，回来后需手动重新开启。

## 使用方式

1. 打开HTTPS网页或本机入口，点击“开启声控”，按提示允许麦克风。
2. 说“截图”“请截图”“帮我截图”或“截个图”。识别为“不要截图”“别截图”“取消截图”等否定指令时不截取。
3. 页面截取当前国画，显示PNG缩略图及“下载 PNG”，并尝试自动保存。浏览器未自动下载时，点击缩略图或下载链接重试。
4. 用“停止声控”结束监听；沉浸模式的短按钮显示“声控／停听”。手动“存画”始终可用。

只处理最终识别结果，尚未确认的中间文字不触发。每次有效截图有2.5秒冷却；同一条最终结果和它的多个候选只处理一次，新一句相同指令在冷却后仍可再次截图。否定指令用于避免误截图，停止监听请使用开关。

手动和声控均调用同一个`renderer.exportPng()`。PNG包含当时的山水、花朵与水纹，不包含摄像头画面、音频、界面按钮或缩略图卡片。识别到指令后会提供下载入口，实际文件保存由浏览器决定。

## 权限与隐私

- 摄像头手部识别在浏览器本机计算，不上传摄像头画面。
- 音乐由本机Web Audio合成，不使用麦克风。
- 声控使用浏览器的SpeechRecognition或webkitSpeechRecognition，可能依赖在线识别服务。本应用不录制或保存音频，也不保存语音转写。
- 同源麦克风请求已在`netlify.toml`与`public/_headers`中设为`microphone=(self)`；实际授权仍由浏览器及系统控制。

网页的“不支持”提示以当前浏览器能力检测为准。浏览器、系统、网络与识别服务不同，语音支持及准确率也会不同；本版本尚未进行真人麦克风实测。

## 常见状态

| 页面提示 | 处理方式 |
| --- | --- |
| 麦克风权限未开启／服务未允许 | 检查浏览器与系统麦克风权限，再手动开启声控；也可直接存画 |
| 网络连接失败 | 检查网络或语音服务可用性，再手动重试；不会持续自动重连 |
| 麦克风暂时无法使用 | 检查设备和其他应用占用，处理后重试 |
| 暂未听到语音 | 继续等待并清楚说出指令；识别自然结束时可延时恢复监听 |
| 多次中断 | 自动恢复已停止，点击重新开启，或使用存画 |
| 浏览器不支持 | 使用页面现有的存画按钮 |

## 模块与生命周期

`VoiceCapture(onCapture, onStatus)`提供`start()`、`stop()`、`dispose()`。构造时只探测支持，不创建识别器；`start()`才开始中文连续识别，设置`lang='zh-CN'`、`continuous=true`、`interimResults=false`。

状态字段为`enabled`、`listening`、`message`、`supported`。`enabled`代表用户的监听意图，`listening`代表原生监听已开始，自动恢复等待期间可以保持启用。权限、网络和麦克风故障会停止并给出说明；无语音及自然结束可按250／500／1000／2000ms退避恢复，连续短故障最多自动重试四次，正常长会话可持续重连。

`stop()`与`dispose()`取消定时重启、终止原生识别并隔离旧回调。页面在`visibilitychange`隐藏和`pagehide`时调用停止，避免离开页面后继续监听。截图成功、导出失败和可点击下载入口由页面层处理，识别模块只发出一次截图回调。

## 验证记录与限制

- 声控模块22项单元测试通过：支持检测、显式开启、肯定／否定语句、最终结果、候选去重、冷却、重连、故障分类、停止及迟到回调均有覆盖。
- 本地构建页面18项集成检查通过，使用模拟SpeechRecognition结果与真实PNG下载，覆盖两个开关、默认关闭、下载重试入口、否定指令、重复结果、错误、后台停止及390px布局。
- 上述检查没有调用真实麦克风，不证明真人口音、环境噪声、识别服务联网情况或手机系统兼容性；当前仍可用存画按钮完成保存。

本地构建验收记录：`output/playwright/voice-built-result.json`；复现脚本：`output/playwright/voice-capture-integration.mjs`。沉浸控件无遮挡另见`output/playwright/dwell-voice-built-result.json`。`output/`不纳入公开仓库。本文件记录本地验证，本次改动的部署状态另行确认。
